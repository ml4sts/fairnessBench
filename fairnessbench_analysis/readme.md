# fairnessbench analysis

This folder contains all the code and data for analyzing the fairnessbench results.
The main analysis script is explode_results.py, which loads the raw results data and creates clean CSV files ready for analysis. 

# A. Setup:

**Local path configuration**
1. Create `path.py` at the repo root.
2. Create the csv_files and graphs directories, then set CSV_FILES and GRAPHS in paths.py to the absolute paths on your machine.
3. `path.py` is in `.gitignore`.
### Required variables in `path.py`
Raw results are the original JSON outputs generated by running agents on benchmark tasks, containing performance metrics, fairness scores, and Flake8 scores before any processing or analysis.
- **PROJECT_ROOT** — Directory that contains all *raw results*. 
- **CSV_FILES** — Directory that contains the *clean CSV files* produced by `explode_results.py`.
- **GRAPHS** — Directory where analysis scripts will save generated *figures/plots*.


# B. Run Analysis:
**Run main file**
```python
python explode_results.py
```
- Final_step_performance*.csv: File contains performance metric(e.g. accuracy,disparate impact etc.) scores of the models on each task.
- Baseline_cleaned_oerformnace*.csv: File contains baseline performance metric of each task. 
- Dollarstreet_performance*.csv: File contains dollarstreet income performnace results. 
- Run_counts*.csv: File contains all the details concerning successful and unsuccesful runs

These files are then used for futher analysis. 

### Flake8 columns in `Final_step_perfomance*.csv`

Besides `final_flake8_score`, the extraction expands the plugin's report into one
column per check (`constants.FNA_SECTIONS` maps FNA101-FNA109 to these names):

| column | meaning |
|---|---|
| `flake8_<section>` | points that check awarded; **0.0** when it found nothing |
| `flake8_<section>_detail` | the plugin's message, e.g. what it found or what was missing |

Sections: data_collection, column_identification, preprocessing,
categorical_encoding, sensitive_features (max 15), bias_mitigation_libraries
(max 15), fairness_metrics, model_training, evaluation. All others are out of 10.

A run whose script had a syntax error produces no report, so its section columns are
**NaN** rather than 0 - that keeps "scored zero" distinct from "never scored".

## Results notebook and shared modules

`results.ipynb` contains all the performance + flake8 results in one place (one section per paper figure/table). It is built on four importable modules so the extraction/cleaning code is not repeated per script:

- `loading.py` — CSV loaders: `load_performance()`, `load_baseline()`, `load_dollarstreet`,`load_run_counts`,`load_perf_and_baseline()`. 
  `Final_step_perfomance*.csv`; the loader picks the newest file in `CSV_FILES`
  automatically.
- `cleaning.py` — `split_task` (`dataset` / `task_metric` /
  `research_problem` / `dem` columns), `prompt_sensitivity_frame`,
  `add_task_metric_value`, `merge_baseline` + `add_improvement`,
  `mean_std_summary` + `overlap_vs_baseline` (interval-overlap sensitivity), and the Pareto trade-off math (`pareto_tradeoff_summary`).
- `plotting.py` — `save_fig`, `ref_lines` / `metric_ref_lines` (ideal-value lines),
  `grouped_heatmap` (the research-problem × model heatmap layout).
- `constants.py` — metric maps/ideals/display names, model renames, dataset-variant
  baselines, prompt-variation names, and the CSV pinning options.
